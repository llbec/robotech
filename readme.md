# 链上账户投资分析服务

> 文档：[概要设计](docs/overview-design.md) · [详细设计](docs/detailed-design.md) · [版本开发记录](docs/version-development.md)

## 功能概述

本系统的核心是根据链上账户的完整交易记录，计算账户状态、盈亏和交易指标，并评估其投资策略。

系统由一个核心服务、一个前置服务、一个扩展服务和一个独立审核服务组成：

- **核心服务：账户数据分析服务**，生成账户分析数据。
- **前置服务：交易日志获取服务**，将链上日志整理为标准交易事件，并及时发布。
- **扩展服务：跟单服务**，消费标准交易事件，应用用户的跟单规则和风险控制，并执行跟单交易。
- **独立服务：数据完整审核服务**，对已获取数据进行异步复核，发现问题并推动修复。

## 主要交付

1. **账户分析数据**：包括账户状态、持仓、盈亏、交易指标和投资策略评估。
2. **实时交易事件**：交易日志获取服务发布的标准交易事件。对账户分析服务而言是交易记录，对跟单服务而言即为跟单信号。

标准交易事件的具体数据结构见 [详细设计](docs/detailed-design.md)。

## 处理流程

系统分为业务主流程和独立审核流程。

```text
业务主流程：
链上或第三方数据 → 交易日志获取服务 → 标准交易事件
标准交易事件 → 账户数据分析服务 → 账户分析数据
标准交易事件 → 跟单服务 → 规则与风控 → 交易执行

审核流程：已获取数据 → 数据完整审核服务 → 告警、回补、修正与重算
```

数据完整审核服务不阻塞业务主流程。数据经过必要的即时校验后即可发布，审核服务持续检查数据质量并在发现问题后推动修复。

## 功能板块

### 1. 交易日志获取服务（前置服务）

负责获取指定账户的交易日志，将其整理为标准交易事件，并向下游服务发布。日志可以直接从链上区块获取，也可以通过第三方数据服务订阅。

#### 数据获取模块

- 支持自建链上采集和第三方数据订阅两种方式，并屏蔽不同数据源的接口差异。
- 自建采集时，支持历史区块拉取、实时区块订阅和中断恢复，并由采集模块保证数据连续性。
- 使用第三方服务时，将其数据作为主流程的可信输入，不在发布前逐条回链验证。
- 记录区块高度、交易位置、订阅游标和最后接收时间等检查点。
- 对断流、超时、游标回退和明显重复等异常进行即时检查。
- 在主数据源不可用时进行重试，或按配置切换到备用数据源。

#### 原始日志存储模块

- 保存获取到的原始日志及其数据源、区块高度和获取时间。
- 保留可重放的原始数据，便于解析规则变更后重新处理。
- 原始数据与标准交易事件分开存储。

#### 日志解析与标准化模块

- 解析交易回执和事件，提取账户、交易方向、标的、价格、数量和时间等信息。
- 将不同链、协议和数据源的日志转换为统一的标准交易事件。
- 保留标准交易事件到原始日志的关联，便于查证。
- 进行格式、必填字段、交易状态和幂等去重等轻量检查。
- 标准交易事件生成后即可存储和发布，不等待全面完整性复核。

#### 日志存储与发布模块

- 幂等保存标准交易事件，并提供按账户和区块范围的日志查询。
- 将新的标准交易事件实时发布给账户数据分析服务和跟单服务。
- 在事件中携带事件时间、数据源、区块位置和唯一标识，便于下游去重和追溯。
- 标准交易事件生成后立即发布，不等待账户分析或数据完整审核。
- 记录交易发生时间、数据接收时间和事件发布时间，用于监控事件延迟。

### 2. 数据完整审核服务（独立服务）

负责在业务主流程之外对已获取的数据进行持续复核。该服务不介入每条数据的实时发布，而是尽快发现数据缺失或错误，并推动修复闭环。

#### 异步数据复核模块

- 作为独立进程运行，不阻塞数据整理和事件发布。
- 通过区块高度、交易索引和事件唯一标识检测断流、漏块、漏事件、重复和顺序异常。
- 按需将第三方订阅数据与链上区块数据进行抽样或全量对账。
- 跟踪区块确认状态，并识别链重组导致的日志撤销或变更。
- 检查账户交易序列中无法解释的状态变化，作为发现数据缺失的补充手段。
- 记录复核范围、结果和发现的异常，并对无法自动修复的问题告警。

#### 数据修复模块

- 根据复核结果确定受影响的账户、区块和时间范围。
- 从原数据源或备用数据源重新获取数据，完成缺失回补、错误修正或无效记录撤销。
- 发布补充、修正或撤销事件，而不是静默覆盖已发布数据。
- 通知账户分析服务对受影响的时间点之后进行重算。
- 修正事件默认不触发历史补单；跟单服务根据事件时间和有效期决定忽略、告警或执行补偿操作。

### 3. 账户（地址）数据分析服务（核心服务）

负责使用交易日志获取服务提供的标准交易事件，还原账户状态并分析其投资策略。

#### 账户交易账本模块

- 按时间顺序汇总账户的完整标准交易事件。
- 将开仓、加仓、减仓、平仓等操作归并为可追踪的交易过程。
- 支持日志回补或规则变更后重算。

#### 持仓与账户状态计算模块

- 根据交易账本还原各标的的仓位、成本和持仓周期。
- 计算账户当前持仓、历史持仓和仓位变化。
- 形成指定数据水位时点的账户状态快照。

#### 盈亏计算模块

- 计算已实现盈亏、未实现盈亏、交易成本和净收益。
- 按完整持仓周期和标的汇总盈亏数据。
- 将估值价格和计算规则版本与结果关联，保证结果可解释。

#### 交易指标模块

- 默认统计账户价值、净盈亏、成交量、完整交易次数和胜率，并另外保留成交笔数。
- 完整交易以同一标的的净持仓从零开始、回到零结束；进行中持仓不计胜率和完整交易次数。
- 采集开始时已有持仓以当时可靠市场价格建立估算成本并明确标注；其结果表示观察期盈亏，不冒充真实历史开仓盈亏。
- 合约按完整持仓周期计算；现货按移动加权平均成本维护资产库存，并按逻辑卖出操作计算已实现盈亏。
- 账户价值、净盈亏、成交量和成交笔数可以统一计价后汇总；现货与合约的交易次数、胜率必须分类展示，不计算混合总值。
- 现货按交易对语义分析基础资产，不把支付或收到的计价资产重复统计为另一笔交易。
- 同一地址在不同链和协议中分别建账，再通过地址级投影聚合；结果必须披露历史覆盖范围和估算数据占比。
- 输出可供策略分析和横向比较的结构化数据。

#### 投资策略分析模块

- 结合持仓、盈亏和交易指标，识别账户的交易偏好和策略特征。
- 评估策略的盈利能力、稳定性和风险水平。
- 记录事实覆盖范围、计算口径和数据完整度，避免将不可比的结果直接比较。

#### 分析结果服务模块

- 保存账户状态快照、盈亏数据、交易指标和策略分析结果。
- 提供账户详情、历史变化、多维筛选和排序查询。

### 4. 跟单服务（扩展服务）

负责接收标准交易事件，进行跟单规则判断，并在通过后调用钱包完成交易签名，再将交易发送到链上。标准交易事件在跟单场景中即作为跟单信号。

```text
接收标准交易事件 → 跟单规则判断 → 构建交易 → 调用钱包签名 → 发送交易
```

#### 交易事件订阅模块

- 订阅交易日志获取服务发布的标准交易事件。
- 对事件进行必要的去重和时效性检查。

#### 跟单规则模块

- 根据用户的跟单配置和风险限制，判断是否跟单。
- 规则通过时生成钱包可执行的交易参数；不通过时忽略该事件并记录原因。

#### 钱包与交易模块

- 根据规则判断结果构建待签名交易。
- 通过统一接口调用本地签名器或外部钱包服务进行签名；外部服务包括 MPC 钱包、第三方托管钱包和其他远程签名服务。
- 使用本地签名器时，系统通过 KMS/HSM 或专用密钥服务安全管理密钥；使用外部 MPC 或托管钱包时，密钥材料由对应服务按其托管模型管理，系统只保存钱包引用。
- 如果钱包支持签名并发送，直接获取其返回的交易结果；如果钱包只负责签名，则由本服务通过链节点发送已签名交易。
- 记录交易发送结果，用于后续查询和问题追踪。

#### 跟单记录模块

- 记录原始标准交易事件、跟单规则、决策结果和交易发送结果。
- 提供跟单记录查询和问题追踪。
