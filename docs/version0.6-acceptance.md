数据库测试使用隔离测试库和固定来源样本。通过内容包括：

1. 地址去重、分页、容量竞争、重复操作幂等及 400/401/404/409 错误透传。
2. 两账户事实身份、水位、租约和会话隔离；暂停撤销旧代次提交资格。
3. 旧归档 WS 消息在恢复后可以保存事实，但不能生成新候选；快照不产生候选。
4. 账户 A 的任务 panic 后自动重建；A 失败或暂停时 B 继续采集。
5. 暂停前的发布队列继续投递；A 投递失败时 B 仍有发送机会。
6. 共享 HTTP 并发与权重预算、WS 连接预算、数据库角色权限。
7. v0.5 数据迁移保留既有事实、水位及发布激活边界，重复迁移不重复登记。

## 2. 服务器待验

本机没有 Docker，尚未执行 Docker 镜像构建与 Compose 验收，也未对真实来源进行多账户完整性对账。这些项目不记为 PASS。

在项目根目录执行升级：

```sh
sh scripts/init-v0.6.sh
docker compose up --build -d
```

按 [开发文档](version0.6.md#102-手动验证步骤) 添加至少两个真实账户，再执行：

```sh
sh scripts/verify-v0.6.sh --fixture-tests --lifecycle --database-fault --wait-seconds 180
```

该命令会短暂重启应用并停止数据库。固定样本使用本次独立测试库，结束后清理该测试库；不会向部署账户写入伪造成交。真实账户不足两个时，多账户持续更新测试返回 SKIP。

PASS 表示对应检查通过；FAIL 需要处理；SKIP 表示未验证。脚本不自动添加、暂停或恢复部署账户。真实账户暂停与恢复、暂停区间补偿及实时成交发布，按开发文档手动步骤执行；来源没有实际成交时不能认定这些场景通过。

## 3. 接口及配置变更

- 监控列表返回管理信息，采集状态位于每项的 collection 字段；详情使用账户登记 ID。
- 发布状态不带 account 时返回汇总，带 account 时返回对应账户状态。
- 新部署允许配置中的旧单账户字段为空，通过管理接口添加账户。升级保留原账户和水位；暂停状态保存在数据库，重启不会自动恢复。
- 管理写操作使用 secrets/watch-management-token；默认最多 5 个活动账户，可配置但不超过 10 个。

统一接口契约见 [api.md](api.md)，验收命令见 [verify.md](verify.md)。
